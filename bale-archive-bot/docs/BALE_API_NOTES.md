# Bale API Notes

> ⚠️ This file is (re)generated by `python scripts/api_probe.py` against a real
> test group. Run the probe before the first deployment and after any Bale
> platform update. The sections below summarise what is already established
> from the official docs (https://docs.bale.ai) and what the probe verifies.

## Established from official documentation

| Fact | Consequence in this codebase |
|------|------------------------------|
| `Update` has only `message`, `edited_message`, `callback_query` | join/leave detection via `new_chat_members` only (`group_intake.register_group_events`) |
| `getUpdates` has only `offset`, `limit` (1..100); no long-polling | adaptive short-interval loop in `app/main.py` with manual offset |
| Webhook: only `url` param; ports 443/88 | secret random path `/webhook/<random>`; Caddy terminates TLS |
| `getChatMember` does not exist | admins tracked in `ADMIN_USER_IDS` + `users.is_admin` |
| `editMessageText` accepts `reply_markup`; no `editMessageReplyMarkup` | all keyboard updates send text+keyboard together via `safe_edit()` |
| `callback_data` ≤ 64 bytes | ASCII scheme `<v>|<act>|<sid>|<arg>` (`app/bale/keyboards.py`) |
| `sendMessage` has no `parse_mode` | plain-text messages only; `FORMATTING_ENABLED=false` |
| `Message` has no `entities` / `media_group_id` | regex hashtag extraction; time-window album buffer (`ALBUM_WINDOW_MS`) |
| `deleteMessage`: < 48h, needs can_delete_messages | `groups.bot_can_delete` tracked; failure degrades gracefully |
| download ≤ 20MB; upload 10MB photo / 50MB other; `file_path` valid 1h | archive channel is the retention layer for 20–50MB files |
| when `animation` is set, `document` is set too | classification order voice→audio→animation→video→photo→document→… |

## Filled in by the probe (`scripts/api_probe.py`)

After running the probe this file will contain:

1. **Method availability table** — which of the 38 approved methods answer
   and which return `error_code` (404 = not routable on this deployment).
2. **Raw update samples** — the exact JSON of one real update per content
   type (text, link, image, video, animation, voice, audio, document,
   location, contact), stored verbatim for `tests/fixtures/updates/`.
3. **Undocumented fields** — whether `media_group_id`, `entities` or
   `message_thread_id` appear in real payloads. If `media_group_id` appears,
   the album buffer automatically prefers it (see `AlbumBuffer._key`).
4. **`answerCallbackQuery`** — confirmed working or not; the capability layer
   (`app/bale/capabilities.py`) also re-checks this on every startup.
5. **Rate-limit behaviour** — outcome codes of a 30-call burst and the shape
   of the first 429 (`parameters.retry_after` presence).

## How to run

```bash
BALE_BOT_TOKEN=<token> PROBE_CHAT_ID=<test group id> python scripts/api_probe.py
# optional: PROBE_WINDOW_S=120 to lengthen the live-update capture window
```

During the capture window, send one of each content type into the test group.
