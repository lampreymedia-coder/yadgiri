# تصمیم فنی رشدیار

## نیازهای اصلی محصول

- اجرای روان روی **اندروید** و **دسکتاپ**
- **سبک‌بودن** و کم‌مصرف‌بودن برای جلوگیری از لگ و کرش
- تجربه کاربری **بسیار ساده** و کم‌اصطکاک
- قابلیت **نصب** مثل اپ
- امکان توسعه سریع برای:
  - برنامه روزانه خودکار
  - هبیت‌ترکر
  - فوکس تایمر
  - گزارش روند رشد

## بنچ‌مارک گزینه‌ها

| گزینه | مزیت | ضعف | جمع‌بندی |
| --- | --- | --- | --- |
| Flutter | یک کدبیس واقعی برای موبایل و دسکتاپ، UI خیلی قوی | در این محیط آماده نبود، حجم و مصرف از PWA بیشتر است | عالی برای نسخه native کامل بعدی |
| React Native + Electron | اکوسیستم بزرگ | دو مسیر متفاوت برای موبایل/دسکتاپ، Electron سنگین است | برای این محصول سبک، بهینه نیست |
| Tauri 2 + Web UI | دسکتاپ بسیار سبک | مسیر موبایل هنوز برای محصول mobile-first به بلوغ Flutter نرسیده | برای نسخه desktop-native آینده عالی است |
| **PWA با React + Vite** | بسیار سبک، نصب‌پذیر، آفلاین، یک کدبیس، سریع برای توسعه | دسترسی native محدودتر از Flutter | **بهترین انتخاب برای نسخه اول سبک و قابل استفاده** |

## چرا در این نسخه PWA انتخاب شد؟

اولویت شما «سبک بودن، کرش نکردن، ساده بودن و اجرا روی موبایل و سیستم» بود. برای همین:

1. **PWA نصب می‌شود** و روی اندروید و دسکتاپ اجرا می‌شود.
2. از نظر حجم و مصرف، از بسته‌های دسکتاپ سنگین بهتر است.
3. توسعه ویژگی‌های UXمحور مثل برنامه خودکار، هبیت‌ترکر و تایمر را سریع‌تر می‌کند.
4. برای نسخه اول، بهترین نسبت بین **کیفیت / سرعت توسعه / سبک بودن** را می‌دهد.

## اگر نسخه بعدی بخواهیم ارتقا بدهیم

- اگر اولویت شد **نسخه native موبایل و دسکتاپ با UI خیلی صیقلی‌تر**: مهاجرت به **Flutter**
- اگر اولویت شد **اپ دسکتاپ super-light**: اضافه‌کردن wrapper با **Tauri**
- اگر خواستیم از همین کد جلو برویم: همین UI وب را می‌توان بعداً داخل wrapper دسکتاپ هم برد

## الهام محصولی

این نسخه از این الگوها الهام گرفته:

- **Notion**: ساختار بلوکی، شفافیت، کم‌اصطکاک بودن
- **Habit trackers**: تیک‌زدن سریع و دیدن استمرار
- **Focus apps**: تایمر، فضای صوتی، ساده‌سازی ورود به کار عمیق
- **Daily planner apps**: دید امروز + ثبت سریع + بازنگری شب
